# Proposal

## Why

Через веб-интерфейс GitHub нельзя создать отдельный тег: тег создаётся только вместе с релизом. Если выпускать версию так, релиз появляется сразу, а `release.yml` по этому тегу находит его и перезаписывает описание своим текстом про установку. Список изменений, который GitHub сгенерировал при создании релиза («What's Changed», ссылки на PR), пропадает. Если тег отправлен из терминала, списка изменений в релизе нет вовсе. В итоге описание релиза зависит от того, как его выпускали.

## What Changes

- Шаг публикации в `release.yml` включает `generate_release_notes: true`: под текстом про установку и конфигурацию добавляется автоматический список изменений GitHub с предыдущего релиза.
- Результат одинаков при обоих способах выпуска: тег из терминала (релиз создаётся черновиком, к нему прикладываются архивы, затем он публикуется) и релиз через интерфейс GitHub (воркфлоу обновляет уже созданный релиз, а не создаёт второй). Повторный запуск воркфлоу не дублирует текст.
- README описывает выпуск через интерфейс GitHub и то, что описание релиза формирует воркфлоу.

Контракт HTTP API не меняется: поля, коды ответов и тексты `detail` остаются прежними.

Вне рамок изменения:
- Сборка, подпись и состав архивов не меняются.
- Окружение `code-signing` и правила создания тегов `v*` не меняются; ручной запуск релиза (`workflow_dispatch`) не добавляется.
- Текст, вписанный вручную при создании релиза через интерфейс, по-прежнему заменяется описанием из воркфлоу.
- Релиз, созданный через интерфейс, публикуется сразу и до конца сборки остаётся без архивов: это поведение GitHub, воркфлоу его не меняет.
- Способов задать директорию с файлами не добавляется.

### Modified Capabilities
- `distribution`: новое требование «Описание релиза» — текст про установку и автоматический список изменений; выпуск через интерфейс GitHub даёт тот же результат, что и тег из терминала.

## Impact

- `.github/workflows/release.yml` — `generate_release_notes: true` в шаге публикации.
- `README.md` — раздел «Создание нового релиза».
- `openspec/specs/distribution/spec.md` — после архивации изменения.
- Python-код и зависимости не меняются.
