# Proposal

## Why

Часть поведения сервиса реализована и закреплена тестами, но не описана в спецификациях `openspec/specs/`. Из-за этого спецификация перестаёт быть полным источником правды: при следующем изменении это поведение можно незаметно сломать или «упростить», не нарушив ни одного требования. Сверка спецификаций с кодом (`app/`, `scripts/branches.py`) и тестами (`tests/`) нашла пять таких мест:

- обработка дат создания до 1970 года и повреждённых меток времени в `GET /files` (`file_created_at`, `TestCreatedAt`);
- молчаливый пропуск в списке элементов с петлёй символических ссылок и с именем, которое отвергает ОС (`_stat_listed_item`);
- кэш разрешённого пути к директории в `GET /files/{fileId}`, его перепроверка перед отказом (переключение DFS) и ответ 500 при сбое самой директории (`_resolve_files_directory`, `TestFilesDirectoryCache`);
- команды `scripts/branches.py` (`matrix`, `configure <филиал>`) и их ошибки, на которые опирается CI (`TestBranchesCli`);
- версия `0.0.0` в OpenAPI-схеме при запуске без установки пакета (`app/__init__.py`).

## What Changes

- `file-listing`: в требование «Источник даты создания» добавлен сценарий для дат до 1970 года; новое требование «Повреждённые метки времени» — метки вне диапазона 1–9999 годов; в требование «В список попадают только .txt-файлы» — сценарий о пропуске петель ссылок и недопустимых имён.
- `file-download`: новые требования «Кэш пути к директории» (путь директории разрешается один раз), «Недоступная директория не кэшируется», «Повторная проверка пути из кэша» (перед отказом 400) и «Сбой при разрешении пути директории» (500 `OS error when reading file` без пути в ответе).
- `distribution`: новые требования «Команды scripts/branches.py» (формат вывода `matrix`, содержимое `app/_build_config.py` после `configure`) и «Ошибки в аргументах scripts/branches.py» (неизвестный филиал и неверные аргументы).
- `api-documentation`: в требование «OpenAPI-схема» добавлен сценарий запуска без установленного пакета (версия `0.0.0`).
- Тест для единственного непокрытого тестами поведения — версии `0.0.0` без `app/_version.py`.

Изменение только описывает существующее поведение. Код приложения и скриптов не меняется. Контракт HTTP API не меняется: поля, коды ответов и тексты `detail` остаются прежними.

Вне рамок изменения:
- Исправление или изменение описываемого поведения (например, выбор других значений для повреждённых меток времени).
- Dependabot (`.github/dependabot.yml`): он не влияет на поведение сервиса и сборки и описан в `openspec/config.yaml`.
- Соглашения о стиле кода, линтере и покрытии: они описаны в `openspec/config.yaml`.
- Способы задать директорию с файлами при запуске не добавляются; кэш пути к директории берёт ключ только из зашитого в сборку пути.

## Impact

- `openspec/specs/file-listing/spec.md`, `openspec/specs/file-download/spec.md`, `openspec/specs/distribution/spec.md`, `openspec/specs/api-documentation/spec.md` — после архивации изменения.
- `tests/test_main.py` — тест версии `0.0.0` при отсутствии `app/_version.py`.
- `app/__init__.py` — только если тест покрывает ветку: снять `# pragma: no cover` с `except ImportError`. Поведение не меняется.
- `README.md` не меняется: API и конфигурация остаются прежними.
