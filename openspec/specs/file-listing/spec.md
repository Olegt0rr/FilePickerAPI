# file-listing Specification

## Purpose
Получение списка .txt-файлов из настроенной директории с разделением на доступные и недоступные для импорта, чтобы фронтенд мог показать пользователю, какие файлы можно выбрать.

## Requirements

### Requirement: Эндпоинт списка файлов
Сервис SHALL предоставлять эндпоинт `GET /files`, который возвращает JSON-объект ровно с двумя полями: `availableFiles` и `unavailableFiles`, каждое из которых является массивом описаний файлов.

#### Scenario: Успешный запрос списка
- **WHEN** клиент выполняет `GET /files`, а настроенная директория существует и доступна для чтения
- **THEN** сервис отвечает статусом 200 и JSON-объектом с полями `availableFiles` и `unavailableFiles`

#### Scenario: Пустая директория
- **WHEN** клиент выполняет `GET /files`, а в директории нет ни одного .txt-файла
- **THEN** сервис отвечает статусом 200 и телом `{"availableFiles": [], "unavailableFiles": []}`

### Requirement: Формат описания файла
Каждый элемент списков SHALL содержать поля в camelCase:
- `id` — идентификатор файла, равный имени файла; используется в `GET /files/{fileId}`;
- `name` — имя файла с расширением;
- `size` — размер файла в байтах (целое число);
- `createdAt` — дата и время в формате ISO 8601 в UTC (см. «Источник даты создания»).

#### Scenario: Метаданные файла
- **WHEN** в директории лежит файл `test1.txt` размером 14 байт
- **THEN** в ответе присутствует элемент с `id` = `test1.txt`, `name` = `test1.txt`, `size` = 14 и заполненным `createdAt`

### Requirement: Источник даты создания
В качестве `createdAt` сервис SHALL использовать время создания файла, если ОС его отдаёт, иначе — время последнего изменения. Windows отдаёт время создания; Linux — нет.

#### Scenario: Windows
- **WHEN** сервис работает как `FilePickerAPI.exe` под Windows, а файл создан в понедельник и изменён в пятницу
- **THEN** `createdAt` равен времени создания в понедельник

#### Scenario: Linux
- **WHEN** сервис запущен из исходников под Linux, а файл создан в понедельник и изменён в пятницу
- **THEN** `createdAt` равен времени изменения в пятницу

### Requirement: В список попадают только .txt-файлы
Сервис SHALL включать в ответ только файлы, расположенные непосредственно в настроенной директории, с расширением `.txt` (без учёта регистра). Поддиректории и их содержимое, а также файлы с другими расширениями MUST NOT попадать ни в один из списков.

#### Scenario: Файлы других форматов игнорируются
- **WHEN** в директории лежат `report.txt` и `document.pdf`
- **THEN** `report.txt` присутствует в ответе, а `document.pdf` отсутствует в обоих списках

#### Scenario: Расширение в верхнем регистре
- **WHEN** в директории лежит файл `REPORT.TXT` размером меньше 10 МиБ
- **THEN** файл попадает в `availableFiles`

#### Scenario: Директории игнорируются
- **WHEN** в настроенной директории есть поддиректории `subdir` и `folder.txt`
- **THEN** поддиректории и файлы внутри них отсутствуют в обоих списках

#### Scenario: Битые ссылки и исчезнувшие файлы пропускаются
- **WHEN** в директории есть битая символическая ссылка `broken.txt` или файл удалён между чтением списка и чтением его атрибутов, а сама директория на месте
- **THEN** такой элемент отсутствует в ответе, а остальные файлы возвращаются со статусом 200

#### Scenario: Директория пропала после перечисления
- **WHEN** директория (например, сетевая папка) пропала после того, как сервис получил список её элементов, и файлы уже не находятся
- **THEN** сервис отвечает статусом 404 и `detail` = `Files directory not found`, а не пустым списком

### Requirement: Символические ссылки в списке
Символическая ссылка SHALL попадать в список, только если её можно скачать через `GET /files/{fileId}`: цель ссылки — файл `.txt`, лежащий непосредственно в настроенной директории. Ссылки на файлы в поддиректориях, за пределами директории или с другим расширением MUST NOT попадать в список.

#### Scenario: Ссылка на файл в директории
- **WHEN** `link.txt` — символическая ссылка на `test1.txt` в той же директории
- **THEN** `link.txt` присутствует в `availableFiles`, и `GET /files/link.txt` отдаёт содержимое `test1.txt`

#### Scenario: Ссылка в поддиректорию
- **WHEN** `link.txt` — символическая ссылка на `subdir/inner.txt`
- **THEN** `link.txt` отсутствует в обоих списках

#### Scenario: Ссылка на файл другого формата
- **WHEN** `link.txt` — символическая ссылка на `document.pdf` в той же директории
- **THEN** `link.txt` отсутствует в обоих списках

### Requirement: Разделение по доступности для импорта
Файл SHALL считаться доступным для импорта, если его расширение `.txt` и размер строго меньше 10 МиБ (10 485 760 байт). Доступные файлы SHALL возвращаться в `availableFiles`, остальные .txt-файлы (размером 10 МиБ и больше) — в `unavailableFiles`.

#### Scenario: Маленький файл доступен
- **WHEN** в директории лежит .txt-файл размером 1 024 байта
- **THEN** файл находится в `availableFiles`

#### Scenario: Файл ровно 10 МиБ недоступен
- **WHEN** в директории лежит .txt-файл размером ровно 10 485 760 байт
- **THEN** файл находится в `unavailableFiles`

#### Scenario: Файл больше 10 МиБ недоступен
- **WHEN** в директории лежит .txt-файл размером 15 МиБ
- **THEN** файл находится в `unavailableFiles`

### Requirement: Сортировка по дате
Сервис SHALL сортировать каждый из списков по `createdAt` в порядке убывания (новые файлы первыми).

#### Scenario: Новые файлы первыми
- **WHEN** в директории лежат два доступных .txt-файла, `old.txt` создан раньше `new.txt`
- **THEN** в `availableFiles` элемент `new.txt` идёт перед `old.txt`

### Requirement: Некорректная настроенная директория
Если настроенная директория не существует, сервис SHALL отвечать на `GET /files` статусом 404 и `detail` = `Files directory not found`. Если настроенный путь указывает не на директорию, сервис SHALL отвечать статусом 400 и `detail` = `Files path is not a directory`.

#### Scenario: Директория не существует
- **WHEN** настроенная директория отсутствует или ОС сообщает, что сетевой путь не найден
- **THEN** `GET /files` отвечает статусом 404 и `detail` = `Files directory not found`

#### Scenario: Путь указывает на файл
- **WHEN** настроенный путь указывает на обычный файл
- **THEN** `GET /files` отвечает статусом 400 и `detail` = `Files path is not a directory`

### Requirement: Ошибки чтения директории
При ошибке ОС во время проверки директории или чтения её содержимого (кроме «путь не найден») сервис SHALL отвечать HTTP-ошибкой, `detail` которой содержит текст исходной ошибки: 403 с префиксом `Permission denied when reading directory:` при отказе в доступе, 500 с префиксом `OS error when reading directory:` при прочих ошибках ввода-вывода и 500 с префиксом `Unexpected error when reading directory:` при любой другой ошибке.

#### Scenario: Путь в тексте ошибки
- **WHEN** чтение директории завершается ошибкой ОС, текст которой содержит путь к директории
- **THEN** путь попадает в `detail`: это сделано намеренно для диагностики, ведь в отличие от скачивания клиент здесь ничего не передаёт и не может так исследовать файловую систему

#### Scenario: Нет прав на чтение
- **WHEN** у процесса нет прав на чтение содержимого директории
- **THEN** `GET /files` отвечает статусом 403 и `detail`, начинающимся с `Permission denied when reading directory:` и содержащим текст исходной ошибки

#### Scenario: Ошибка ввода-вывода
- **WHEN** при чтении директории возникает ошибка ввода-вывода (например, сбой диска или сети)
- **THEN** `GET /files` отвечает статусом 500 и `detail`, начинающимся с `OS error when reading directory:`

#### Scenario: Непредвиденная ошибка
- **WHEN** при чтении директории возникает любая другая ошибка
- **THEN** `GET /files` отвечает статусом 500 и `detail`, начинающимся с `Unexpected error when reading directory:`
