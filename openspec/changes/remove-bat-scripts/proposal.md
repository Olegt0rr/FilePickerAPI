# Proposal

## Why

После изменения `windows-service` сервис запускается как служба Windows, а `run_test.bat` и `run_production.bat` остаются только для филиалов, которые ещё не переведены. Когда на службу переведены все машины, скрипты больше не нужны, а их поддержка сохраняет риски, ради которых делалась служба: логику запуска на cmd не проверить автотестами, и в ней легко ошибиться (подмена системных утилит, `errorlevel`, `pushd` по UNC-пути).

## What Changes

- **BREAKING (3.0.0):** `run_test.bat` и `run_production.bat` удаляются из репозитория и из сборки. Запуск сервиса — только службой (`FilePickerAPI.exe install`) или `FilePickerAPI.exe` без аргументов в консоли.
- Из спецификации `distribution` удаляется требование «Скрипты запуска для Windows»; в папке сборки и в архиве релиза bat-скриптов нет.
- Дымовая проверка в CI дополнительно проверяет, что в папке сборки нет `*.bat`.
- README, текст релиза, Purpose спецификации `distribution`, `openspec/config.yaml` и `CLAUDE.md` больше не упоминают bat-скрипты как способ запуска.

Контракт HTTP API не меняется. Способов задать директорию с файлами при запуске не появляется.

Вне рамок изменения:
- Сама служба и её поведение — это `windows-service`.
- Перевод филиалов на службу — делается до этого изменения; оно выполняется, только когда переведены все машины.

### Modified Capabilities
- `distribution`: требование «Скрипты запуска для Windows» удаляется. «Сборка для Windows» — в папке сборки нет bat-скриптов. «Автоматический релиз» — архив содержит папку без bat-скриптов.

## Impact

- Удаляются `run_test.bat` и `run_production.bat`; правило `*.bat` в `.gitattributes` удаляется, если других bat-файлов не осталось.
- `.github/workflows/build-exe.yml` — удаляется копирование bat в папку сборки; `.github/scripts/service-smoke.ps1` — проверка отсутствия `*.bat`.
- `.github/workflows/release.yml`, `README.md`, `openspec/config.yaml`, `CLAUDE.md`, Purpose в `openspec/specs/distribution/spec.md`.
- Эксплуатация: на филиале, который ещё работает через задачу Планировщика с `run_production.bat`, обновление до 3.0.0 сломает запуск. Перед релизом 3.0.0 нужно убедиться, что все машины переведены на службу.
- Зависимость: выполняется после архивации `windows-service`. Дельта `distribution` написана поверх требований в том виде, какой они получат после неё.
