# distribution Specification

## Purpose
Поставка и запуск сервиса на Windows: сборка Nuitka с bat-скриптами, подпись бинарников и автоматические релизы на GitHub с версией из git-тега.

## Requirements

### Requirement: Сборка для Windows
Проект SHALL собираться через Nuitka в режиме standalone: папка `FilePickerAPI` с `FilePickerAPI.exe`, его зависимостями и bat-скриптами, которая запускается без установленного Python. Под каждый филиал из `branches.toml` SHALL собираться своя папка. Режим onefile MUST NOT использоваться: он распаковывает неподписанные файлы во временную папку пользователя, что несовместимо с подписью и WDAC/AppLocker. Сборка SHALL выполняться в CI только после успешного прохождения линтера и тестов.

#### Scenario: Сборка в CI
- **WHEN** в ветку `main`/`master` отправлен коммит или открыт pull request в одну из этих веток
- **THEN** CI запускает ruff и pytest на Linux и, если они прошли, собирает папку `FilePickerAPI` на Windows для каждого филиала из `branches.toml` и публикует её как артефакт `FilePickerAPI-<филиал>` (например, `FilePickerAPI-5400`)

#### Scenario: Тесты упали
- **WHEN** линтер или тесты завершились с ошибкой
- **THEN** сборка не выполняется

#### Scenario: Путь филиала в сборке
- **WHEN** CI собирает папку филиала 5400
- **THEN** перед компиляцией CI сверяет записанный путь с `files_directory` филиала 5400 в `branches.toml` и при расхождении сборка падает; сборки филиалов отличаются только зашитой директорией с файлами

#### Scenario: Ошибка в списке филиалов
- **WHEN** `branches.toml` не проходит проверку (см. «Список филиалов»)
- **THEN** джоб с тестами падает с сообщением о причине, и ни одна сборка не выполняется

### Requirement: Версия из git-тега
Версия проекта SHALL браться только из git-тега (`v2.3.0` → `2.3.0`) и попадать в метаданные пакета, в OpenAPI-схему и в свойства `FilePickerAPI.exe`. Версию MUST NOT поднимать вручную в файлах. Сборки между релизами получают версию вида `2.3.1.dev4+g1a2b3c4`.

#### Scenario: Сборка по тегу
- **WHEN** CI собирает проект по тегу `v2.3.0`
- **THEN** версия сборки — `2.3.0`; если вычисленная версия не совпадает с тегом, сборка падает

#### Scenario: Сборка между релизами
- **WHEN** CI собирает коммит через 4 коммита после тега `v2.3.0`
- **THEN** версия сборки — `2.3.1.dev4+g<хэш>`, а версия в свойствах exe — `2.3.1`

### Requirement: Подпись релизных бинарников
Все неподписанные `exe`/`dll`/`pyd` релизных сборок всех филиалов SHALL подписываться сертификатом Authenticode с меткой времени. Файлы с действительной чужой подписью (например, `python311.dll`) SHALL оставаться как есть, а файл с недействительной подписью MUST останавливать релиз. Сертификат MUST быть доступен только релизным тегам (окружение `code-signing`); без него релиз MUST NOT публиковаться.

#### Scenario: Релиз без сертификата
- **WHEN** секреты сертификата в окружении `code-signing` не заданы
- **THEN** джоб подписи падает, и релиз не создаётся

#### Scenario: Проверка подписи в pull request
- **WHEN** открыт pull request в `main`/`master`
- **THEN** CI подписывает сборки всех филиалов одноразовым самоподписанным сертификатом тем же скриптом, что и в релизе, не получая доступа к боевому сертификату

### Requirement: Скрипты запуска для Windows
В папке сборки SHALL поставляться два скрипта:
- `run_test.bat` — запускает `FilePickerAPI.exe` в текущем окне консоли с видимым выводом для отладки;
- `run_production.bat` — запускает `FilePickerAPI.exe` в свёрнутом окне в фоне, проверяет, что сервис ответил по HTTP, и пишет итог запуска в журнал пользователя.

Оба скрипта SHALL работать из своей папки независимо от рабочей директории вызывающего и MUST завершаться с сообщением об ошибке, если рядом с ними нет `FilePickerAPI.exe`.

#### Scenario: Запуск в фоновом режиме
- **WHEN** пользователь запускает `run_production.bat` в папке сборки, и сервис начинает отвечать на `http://127.0.0.1:8000/openapi.json` за время ожидания (до 30 попыток с паузой 2 секунды)
- **THEN** сервис работает в свёрнутом окне, в `%LOCALAPPDATA%\FilePickerAPI\startup.log` добавляется строка со словом `started`, датой и временем запуска, а скрипт завершается с кодом 0 (журнал лежит в профиле пользователя, потому что в папку установки у пользователей нет прав на запись)

#### Scenario: Сервис завершился при запуске
- **WHEN** `FilePickerAPI.exe` завершается сразу после старта (например, в `.env` рядом с ним указан `FILES_DIRECTORY`)
- **THEN** `run_production.bat` не ждёт до конца времени ожидания: в журнал добавляется строка со словом `FAILED`, датой, временем и причиной, в консоль выводится сообщение об ошибке, а скрипт завершается с ненулевым кодом

#### Scenario: Windows не дал запустить exe
- **WHEN** Windows отказывается запускать `FilePickerAPI.exe` (например, его блокирует AppLocker или нет прав доступа)
- **THEN** `run_production.bat` пишет в журнал строку со словом `FAILED` и причиной `Windows could not start FilePickerAPI.exe` (Windows не дал запустить exe), а не причиной о завершении exe при запуске, и завершается с ненулевым кодом

#### Scenario: Сервис не ответил за время ожидания
- **WHEN** `FilePickerAPI.exe` работает, но за время ожидания так и не ответил на `http://127.0.0.1:8000/openapi.json`
- **THEN** в журнал добавляется строка со словом `FAILED` и причиной, в консоль выводится сообщение об ошибке, а скрипт завершается с ненулевым кодом; запущенный процесс скрипт не останавливает

#### Scenario: Порт 8000 уже занят
- **WHEN** до запуска на `http://127.0.0.1:8000` уже отвечает HTTP-сервер (например, ранее запущенный экземпляр сервиса)
- **THEN** `run_production.bat` не запускает новый экземпляр, пишет в журнал строку со словом `FAILED` и причиной `port 8000 is already in use` (порт занят) и завершается с ненулевым кодом; уже работающий экземпляр не считается успешным запуском

#### Scenario: Экземпляр уже запущен, но не отвечает
- **WHEN** до запуска на порту 8000 никто не отвечает по HTTP, но процесс `FilePickerAPI.exe` уже есть (ещё стартует или остался от прошлого неудачного запуска)
- **THEN** `run_production.bat` не запускает новый экземпляр, пишет в журнал строку со словом `FAILED` и причиной `FilePickerAPI.exe is already running but does not answer` и завершается с ненулевым кодом, чтобы ответ старого экземпляра позже не был принят за успешный запуск нового

#### Scenario: Нет средства проверки
- **WHEN** в системе нет `curl.exe` в `%SystemRoot%\System32` (Windows старше 10 версии 1803)
- **THEN** `run_production.bat` не запускает сервис, пишет в журнал строку со словом `FAILED` и причиной и завершается с ненулевым кодом

#### Scenario: Запуск из Планировщика заданий
- **WHEN** `run_production.bat` запускается Планировщиком заданий Windows с другой рабочей директорией
- **THEN** скрипт находит `FilePickerAPI.exe` рядом с собой, запускает его с папкой сборки в качестве рабочей, а результат запуска виден в Планировщике по коду выхода (0 — сервис ответил, иначе — ошибка)

#### Scenario: Ошибка без пользователя
- **WHEN** `run_production.bat` завершается с ошибкой в неинтерактивном запуске (Планировщик заданий, нет ввода с консоли)
- **THEN** скрипт не ждёт нажатия клавиши: при доступной консоли окно закрывается само не позже чем через 30 секунд, без консольного ввода скрипт завершается сразу

#### Scenario: Скрипты в сетевой папке
- **WHEN** папка сборки лежит в сетевой папке (UNC-путь), и пользователь запускает скрипт
- **THEN** скрипт переходит в свою папку через `pushd`, а `run_production.bat` запускает exe по исходному UNC-пути, чтобы `popd` в конце (в том числе после ошибки) не отключил временный диск из-под работающего приложения

#### Scenario: Исполняемый файл отсутствует
- **WHEN** пользователь запускает любой из bat-скриптов в папке без `FilePickerAPI.exe`
- **THEN** скрипт выводит `Error: FilePickerAPI.exe not found!`, не запускает сервис и завершается с ненулевым кодом; `run_production.bat` также пишет в журнал строку со словом `FAILED`

#### Scenario: Скрипты не задают директорию
- **WHEN** пользователь запускает любой из bat-скриптов
- **THEN** скрипт не передаёт приложению путь к директории с файлами, и сервис работает с директорией, зашитой при сборке (см. `service-configuration`); проверка запуска в `run_production.bat` обращается только к `http://127.0.0.1:8000` и не добавляет способов задать директорию

### Requirement: Автоматический релиз
При публикации тега вида `vX.Y.Z` из цифр SHALL создаваться GitHub Release, к которому для каждого филиала из `branches.toml` прикреплён архив `FilePickerAPI-<филиал>.zip` с подписанной папкой сборки этого филиала, собранной из этого тега после успешного прохождения тестов. Теги с суффиксом (например, `v2.3.0-rc1`) MUST NOT создавать релиз.

#### Scenario: Публикация тега
- **WHEN** в репозиторий отправлен тег `v2.3.0`
- **THEN** создаётся релиз `v2.3.0` с архивами `FilePickerAPI-5000.zip`, `FilePickerAPI-5100.zip` и `FilePickerAPI-5400.zip`, внутри каждого папка `FilePickerAPI` с подписанным `FilePickerAPI.exe` своего филиала, `run_test.bat` и `run_production.bat`

#### Scenario: Предварительная версия
- **WHEN** в репозиторий отправлен тег `v2.3.0-rc1`
- **THEN** релиз не создаётся

### Requirement: Список филиалов
Филиалы и их директории SHALL перечисляться в `branches.toml` в корне репозитория блоками `[[branch]]` с полями `name` (код филиала из букв, цифр, `-` и `_`) и `files_directory` (путь к директории). Список MUST быть непустым, коды филиалов MUST быть уникальными, а оба поля MUST быть непустыми строками. Добавление филиала SHALL требовать только нового блока в `branches.toml`, без изменений кода.

#### Scenario: Добавление филиала
- **WHEN** в `branches.toml` добавлен блок `[[branch]]` с `name = "5500"` и путём филиала, и коммит отправлен в `main`
- **THEN** CI собирает дополнительный артефакт `FilePickerAPI-5500`, а следующий релиз содержит `FilePickerAPI-5500.zip`

#### Scenario: Повтор кода филиала
- **WHEN** в `branches.toml` два блока с одинаковым `name`
- **THEN** проверка списка завершается ошибкой с указанием повторяющегося кода

#### Scenario: Код филиала без кавычек
- **WHEN** в `branches.toml` указано `name = 5000` (число, а не строка)
- **THEN** проверка списка завершается ошибкой с указанием недопустимого имени, а не падением скрипта
