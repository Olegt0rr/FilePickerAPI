## MODIFIED Requirements

### Requirement: Источник даты создания
В качестве `createdAt` сервис SHALL использовать время создания файла, если ОС его отдаёт, иначе — время последнего изменения. Windows отдаёт время создания; Linux — нет. Метки времени до 1970 года SHALL отдаваться как есть, повреждённые — см. «Повреждённые метки времени».

#### Scenario: Windows
- **WHEN** сервис работает как `FilePickerAPI.exe` под Windows, а файл создан в понедельник и изменён в пятницу
- **THEN** `createdAt` равен времени создания в понедельник

#### Scenario: Linux
- **WHEN** сервис запущен из исходников под Linux, а файл создан в понедельник и изменён в пятницу
- **THEN** `createdAt` равен времени изменения в пятницу

#### Scenario: Дата до 1970 года
- **WHEN** под Windows у файла время создания `1601-01-01T00:00:00Z` (нулевой FILETIME, такое оставляют архиваторы и robocopy)
- **THEN** `GET /files` отвечает статусом 200, а `createdAt` файла = `1601-01-01T00:00:00Z`

### Requirement: В список попадают только .txt-файлы
Сервис SHALL включать в ответ только файлы, расположенные непосредственно в настроенной директории, с расширением `.txt` (без учёта регистра). Поддиректории и их содержимое, а также файлы с другими расширениями MUST NOT попадать ни в один из списков. Элементы, атрибуты которых нельзя прочитать из-за петли символических ссылок или недопустимого с точки зрения ОС имени, SHALL пропускаться без ошибки для всего запроса.

#### Scenario: Файлы других форматов игнорируются
- **WHEN** в директории лежат `report.txt` и `document.pdf`
- **THEN** `report.txt` присутствует в ответе, а `document.pdf` отсутствует в обоих списках

#### Scenario: Расширение в верхнем регистре
- **WHEN** в директории лежит файл `REPORT.TXT` размером меньше 10 МиБ
- **THEN** файл попадает в `availableFiles`

#### Scenario: Директории игнорируются
- **WHEN** в настроенной директории есть поддиректории `subdir` и `folder.txt`
- **THEN** поддиректории и файлы внутри них отсутствуют в обоих списках

#### Scenario: Имя устройства на Windows
- **WHEN** сервис работает под Windows 11, и в директории лежит файл `nul.txt` (имя устройства, см. `file-download`)
- **THEN** файл отсутствует в обоих списках: его нельзя скачать через `GET /files/{fileId}`

#### Scenario: Битые ссылки и исчезнувшие файлы пропускаются
- **WHEN** в директории есть битая символическая ссылка `broken.txt` или файл удалён между чтением списка и чтением его атрибутов, а сама директория на месте
- **THEN** такой элемент отсутствует в ответе, а остальные файлы возвращаются со статусом 200

#### Scenario: Петли ссылок и недопустимые имена пропускаются
- **WHEN** в директории есть `loop.txt` — символическая ссылка сама на себя, или элемент, имя которого ОС отвергает при чтении атрибутов (слишком длинное имя)
- **THEN** такой элемент отсутствует в обоих списках, а остальные файлы возвращаются со статусом 200

#### Scenario: Директория пропала после перечисления
- **WHEN** директория (например, сетевая папка) пропала после того, как сервис получил список её элементов, и файлы уже не находятся
- **THEN** сервис отвечает статусом 404 и `detail` = `Files directory not found`, а не пустым списком

## ADDED Requirements

### Requirement: Повреждённые метки времени
Если метка времени файла выходит за пределы 1–9999 годов (метаданные повреждены), сервис SHALL показывать файл с `createdAt`, равным максимальной дате (`9999-12-31T23:59:59.999999Z`) для меток в будущем или минимальной (`0001-01-01T00:00:00Z`) для меток в прошлом, и MUST NOT отвечать ошибкой на весь запрос.

#### Scenario: Повреждённая метка времени
- **WHEN** у одного из файлов метка времени лежит за пределами 9999 года
- **THEN** `GET /files` отвечает статусом 200, файл присутствует в ответе с `createdAt` = `9999-12-31T23:59:59.999999Z`, а остальные файлы возвращаются как обычно
