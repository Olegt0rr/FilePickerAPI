# service-configuration Specification

## Purpose
Настройка и запуск сервиса: какая директория обслуживается, какие источники допускаются политикой CORS и на каком адресе сервис принимает запросы.

## Requirements

### Requirement: Директория с файлами зашивается в сборку
Сервис SHALL обслуживать файлы из одной директории, путь к которой задаётся при сборке и зашивается в исполняемый файл. Текущее значение — сетевая папка `\\localmq.neadru.local\Payments\5100\CENTER\RSB`.

#### Scenario: Запуск без настройки
- **WHEN** сервис запущен без каких-либо параметров
- **THEN** `GET /files` и `GET /files/{fileId}` работают с директорией `\\localmq.neadru.local\Payments\5100\CENTER\RSB`

### Requirement: Пользователь не может подменить директорию
Пользователь на месте установки MUST NOT иметь возможности подменить директорию, из которой сервис отдаёт файлы. Сервис MUST NOT принимать путь к директории при запуске: ни через переменные окружения, ни через `.env`, аргументы командной строки, конфигурационные файлы рядом с exe или параметры bat-скриптов. Сменить директорию можно только новой сборкой; схема «один exe плюс путь в конфиге рядом» не допускается.

#### Scenario: Переменная окружения игнорируется
- **WHEN** сервис запущен с переменной окружения `FILES_DIRECTORY=/app/files`
- **THEN** сервис по-прежнему обслуживает зашитую при сборке директорию

#### Scenario: Путь в `.env` не принимается
- **WHEN** в файле `.env` в рабочей директории указан `FILES_DIRECTORY`
- **THEN** сервис не запускается и не начинает обслуживать указанную в `.env` директорию

### Requirement: Настройка CORS
Сервис SHALL применять политику CORS ко всем эндпоинтам. Список разрешённых источников SHALL задаваться переменной окружения `CORS_ORIGINS` (или одноимённым параметром в файле `.env` в рабочей директории) в виде строки через запятую; пробелы вокруг элементов и пустые элементы отбрасываются. Если переменная не задана или после разбора список пуст, сервис SHALL разрешать все источники (`*`). Разрешены любые методы и заголовки, а также передача учётных данных.

#### Scenario: Все источники по умолчанию
- **WHEN** `CORS_ORIGINS` не задана, а клиент отправляет запрос с заголовком `Origin: http://example.com`
- **THEN** ответ содержит `Access-Control-Allow-Origin: *`

#### Scenario: Ограниченный список источников
- **WHEN** `CORS_ORIGINS=http://localhost:3000,https://example.com`, а клиент отправляет запрос с `Origin: http://localhost:3000`
- **THEN** запрос обрабатывается, и ответ разрешает этот источник

#### Scenario: Пустое значение
- **WHEN** `CORS_ORIGINS` задана пустой строкой
- **THEN** сервис разрешает все источники

### Requirement: Запуск сервиса
При запуске как приложения (`python -m app` или `FilePickerAPI.exe`) сервис SHALL пытаться создать обслуживаемую директорию, если она не существует (включая родительские директории). Ошибка создания MUST NOT останавливать запуск: сервис пишет предупреждение в лог и продолжает работу. Сервис SHALL принимать HTTP-запросы на всех сетевых интерфейсах (`0.0.0.0`) на порту 8000.

#### Scenario: Директория отсутствует при запуске
- **WHEN** сервис запускается, а обслуживаемой директории нет, но её можно создать
- **THEN** директория создаётся, и сервис начинает принимать запросы на порту 8000

#### Scenario: Сетевая папка недоступна при запуске
- **WHEN** сервис запускается, а сетевая папка недоступна
- **THEN** в лог пишется предупреждение, сервис принимает запросы, а `GET /files` отвечает 404, пока папка не станет доступна

#### Scenario: Доступ по сети
- **WHEN** сервис запущен на машине с адресом `192.168.1.10`
- **THEN** API доступен по адресу `http://192.168.1.10:8000`
