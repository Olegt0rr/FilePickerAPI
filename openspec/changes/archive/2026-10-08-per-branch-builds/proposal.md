# Proposal

## Why

Путь к директории с файлами был зашит прямо в `app/settings.py`. Под каждый новый филиал путь правили в коде и выпускали отдельную сборку (сначала 5000, затем 5100), а пришёл уже третий филиал (5400). Сборки разных филиалов расходились по коммитам: исправление дефекта пришлось бы переносить и пересобирать для каждого филиала вручную.

## What Changes

- Список филиалов и их путей хранится в `branches.toml` в корне репозитория (`[[branch]]` с `name` и `files_directory`). Сейчас там 5000, 5100 и 5400.
- `scripts/branches.py` проверяет список (непустой, уникальные имена из букв, цифр, `-` и `_`, строковые непустые пути), выдаёт его как матрицу для CI (`matrix`) и перед сборкой записывает путь филиала в `app/_build_config.py` (`configure <филиал>`). Сгенерированный файл не хранится в git.
- `app/settings.py` берёт `Settings.files_directory` из `app._build_config`; если файла нет (запуск из исходного кода), используется `./files`. Любая другая ошибка импорта конфига останавливает запуск, а не переключает на `./files`. Путь остаётся `ClassVar`.
- CI (`build-exe.yml`) из одного коммита собирает отдельную Nuitka-сборку под каждый филиал (матрица по `branches.toml`), перед сборкой сверяет записанный путь с `branches.toml`, принудительно включает `app._build_config` в сборку и публикует артефакты `FilePickerAPI-<филиал>`. `sign-smoke` подписывает все сборки.
- Релиз подписывает сборки всех филиалов и прикрепляет архив `FilePickerAPI-<филиал>.zip` на каждый филиал вместо одного `FilePickerAPI-Windows.zip`.
- README описывает сборку под филиалы.

Контракт HTTP API не меняется: поля, коды ответов и тексты `detail` остаются прежними.

Вне рамок изменения:
- Способов задать директорию при запуске не появляется: ни переменных окружения, ни `.env`, ни аргументов, ни конфигов рядом с exe, ни параметров bat-скриптов. Сменить путь филиала можно только правкой `branches.toml` и новой сборкой.
- Схема «один exe плюс путь в конфиге рядом» отклонена, хотя она быстрее собирается.
- bat-скрипты, подпись (`sign.ps1`) и версия из git-тега не меняются.

## Capabilities

### New Capabilities

### Modified Capabilities
- `service-configuration`: требование «Директория с файлами зашивается в сборку» — путь берётся из сборки филиала, без неё используется `./files`, сломанный конфиг сборки останавливает запуск.
- `distribution`: сборка, подпись и релиз выполняются под каждый филиал из `branches.toml`; добавлено требование к списку филиалов.

## Impact

- `branches.toml`, `scripts/branches.py` — новые файлы.
- `app/settings.py` — источник пути.
- `.github/workflows/build-exe.yml`, `.github/workflows/release.yml` — матрица по филиалам, артефакты и архивы на филиал.
- `pyproject.toml` — ruff для `scripts/` (INP001).
- `.gitignore` — `app/_build_config.py`.
- `tests/test_branches.py` — тесты списка филиалов и источника пути.
- `README.md`, `openspec/config.yaml`.
- Время CI растёт пропорционально числу филиалов: на каждый филиал отдельный Windows-джоб Nuitka.
