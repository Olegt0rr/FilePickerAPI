# Proposal

## Why

CI собирал каждый филиал в отдельном Windows-джобе матрицы. Код и зависимости у филиалов одни и те же, отличается только `app/_build_config.py`, но каждый джоб заново поднимал раннер, ставил Python и зависимости, скачивал утилиты Nuitka и генерировал C-код. С тремя филиалами это втрое больше Windows-минут на установку, а релизная сборка (без кэша) трижды компилировала всё дерево зависимостей с нуля.

## What Changes

- `build-exe.yml`: один Windows-джоб `build` вместо матрицы. Python, зависимости и кэш Nuitka готовятся один раз, затем шаг сборки в цикле по филиалам из джоба `test` выполняет `configure`, сверяет записанный путь с `branches.toml` и собирает Nuitka в `dist/FilePickerAPI-<филиал>/FilePickerAPI`. Сборки после первой берут скомпилированные C-модули из кэша Nuitka этого же джоба, в том числе в релизе по тегу.
- Сборки всех филиалов публикуются одним артефактом `FilePickerAPI` (внутри — папка `FilePickerAPI-<филиал>/FilePickerAPI` на филиал): загрузка артефакта — отдельный шаг, и повторить его по списку филиалов нельзя.
- `sign-smoke` и `release.yml` скачивают артефакт `FilePickerAPI`; раскладка `dist/FilePickerAPI-<филиал>/FilePickerAPI` и `sign.ps1` не меняются.
- Выход джоба `test` переименован из `matrix` в `branches`.

Контракт HTTP API не меняется: поля, коды ответов и тексты `detail` остаются прежними.

Вне рамок изменения:
- Директория по-прежнему компилируется в exe каждого филиала (`app._build_config`). Схемы «один exe плюс путь в конфиге рядом» и «общая сборка плюс подменяемый модуль с путём рядом с exe» отклонены: они дали бы пользователю способ подменить директорию.
- Релизные архивы `FilePickerAPI-<филиал>.zip`, подпись, bat-скрипты и `scripts/branches.py` не меняются.

## Impact

- `.github/workflows/build-exe.yml`, `.github/workflows/release.yml`.
- `README.md`, `openspec/config.yaml`.
- Сборки филиалов идут последовательно: время джоба — одна полная сборка плюс по сборке из кэша на каждый следующий филиал, зато нет повторной установки на каждый филиал и параллельных раннеров.
