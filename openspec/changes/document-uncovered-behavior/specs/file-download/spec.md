## ADDED Requirements

### Requirement: Кэш пути к директории
Чтобы не обращаться к сетевой папке на каждом скачивании, сервис SHALL разрешать путь к настроенной директории (с символическими ссылками и DFS) один раз и брать его из кэша при следующих запросах `GET /files/{fileId}`. Ключом кэша MUST быть только путь, зашитый в сборку (см. `service-configuration`). В кэш SHALL попадать только полностью разрешённый путь: если полное разрешение пути директории завершается ошибкой ОС (например, сетевая папка недоступна), сервис проверяет запрос по частично разрешённому пути и не кэширует его. Если запрошенный файл не лежит в директории из кэша, сервис SHALL перед отказом 400 разрешить путь директории заново и сравнить с ним. Сервис SHALL убрать путь из кэша и отвечать статусом 500 и `detail` = `OS error when reading file`, если путь директории не удаётся разрешить даже частично, если при разрешении обнаружена петля символических ссылок или если при повторной проверке путь из кэша не удаётся разрешить полностью; путь к директории MUST NOT попадать в ответ.

#### Scenario: Путь разрешается один раз
- **WHEN** клиент трижды подряд скачивает `test1.txt`
- **THEN** путь к директории разрешается только при первом запросе, все три ответа — 200

#### Scenario: Сетевая папка переключилась
- **WHEN** после первого скачивания DFS переключил сетевую папку на другой сервер (ссылка директории теперь указывает на другую папку), и клиент снова запрашивает `test1.txt`
- **THEN** сервис разрешает путь директории заново и отдаёт `test1.txt` из новой папки со статусом 200

#### Scenario: Директория появилась позже
- **WHEN** при первом запросе директории ещё нет, а затем она становится доступной
- **THEN** первый запрос получает 404 и `detail` = `File not found`, а следующий отдаёт файл со статусом 200 без перезапуска сервиса

#### Scenario: Сбой при повторной проверке
- **WHEN** путь директории взят из кэша, запрошенный файл в ней не лежит, а повторное разрешение пути директории завершается ошибкой ввода-вывода
- **THEN** сервис отвечает статусом 500 и `detail` = `OS error when reading file`, а не 400, и следующее скачивание разрешает путь директории заново
