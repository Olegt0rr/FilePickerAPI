## ADDED Requirements

### Requirement: Проверка зависимостей на уязвимости
CI SHALL проверять все пакеты, которые ставятся вместе с проектом и его extras (`dev`, `build`, `audit`) на Windows, по базе известных уязвимостей (pip-audit, PyPI Advisory) при push и pull request в `main`/`master`, ежедневно по расписанию и вручную. Проверка MUST завершаться ошибкой, если у пакета есть известная уязвимость или пакет не удалось проверить. Релиз MUST NOT подписываться и публиковаться, если проверка, запущенная для его тега, не прошла. Пропуск конкретной уязвимости SHALL оформляться только явным исключением в workflow с комментарием-причиной.

#### Scenario: Уязвимость в зависимости
- **WHEN** в `pyproject.toml` закреплена версия пакета с известной уязвимостью (например, `starlette==0.50.0`)
- **THEN** проверка падает, а в логе указаны пакет, версия, идентификаторы уязвимости (CVE, GHSA) и версия с исправлением

#### Scenario: Новая CVE без коммитов
- **WHEN** для уже закреплённой версии зависимости опубликована уязвимость, а в репозиторий ничего не отправляли
- **THEN** ближайший ежедневный запуск проверки падает

#### Scenario: Релиз с уязвимой зависимостью
- **WHEN** отправлен тег `v2.3.0`, а проверка зависимостей для него падает
- **THEN** сборки не подписываются, релиз не публикуется
