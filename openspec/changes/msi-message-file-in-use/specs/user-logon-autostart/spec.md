## MODIFIED Requirements

### Requirement: Обновление и откат MSI
Установка MSI новой версии, в том числе другого филиала, поверх установленного SHALL заменять продукт (`MajorUpgrade`). Установка той же или более старой версии поверх MUST отказывать: откат и смена филиала той же версии — удаление продукта и установка нужного MSI. `.env`, созданный администратором в папке установки, MUST сохраняться при обновлении. Работающий экземпляр сервиса SHALL останавливаться мягко, если Windows Installer закрывает его через Restart Manager. Установка, обновление и откат MUST NOT останавливать и перезапускать службу журнала событий (`EventLog`) и зависимые от неё службы, в том числе когда служба держит открытым файл сообщений File Picker API.

#### Scenario: Обновление версии
- **WHEN** установлена версия 2.3.0, в папке установки лежит `.env` с `CORS_ORIGINS`, и администратор ставит MSI версии 2.4.0
- **THEN** установлена 2.4.0, в «Программах и компонентах» один продукт, `.env` на месте, сервис использует те же `CORS_ORIGINS`

#### Scenario: Откат
- **WHEN** установлена версия 2.4.0, администратор удаляет продукт и ставит MSI версии 2.3.0
- **THEN** установлена 2.3.0, `.env` на месте; источник `FilePickerAPI` остаётся зарегистрированным на файле сообщений 2.4.0, а события читаются полностью, потому что коды только добавляются

#### Scenario: Старая версия поверх новой
- **WHEN** установлена версия 2.4.0, и администратор ставит MSI версии 2.3.0, не удаляя продукт
- **THEN** установка отказывает с сообщением об этом, версия 2.4.0 остаётся

#### Scenario: Другой филиал той же версии
- **WHEN** установлен филиал 5400 версии 2.4.0, и администратор ставит `FilePickerAPI-5100.msi` той же версии, не удаляя продукт
- **THEN** установка отказывает с сообщением об этом, сборка 5400 остаётся; после удаления продукта и установки MSI филиала 5100 все файлы совпадают с этим MSI, `.env` на месте

#### Scenario: Сбой обновления
- **WHEN** установлена версия 2.3.0, и установка MSI версии 2.4.0 завершается ошибкой
- **THEN** Windows Installer возвращает 2.3.0 с её файлами и значением `Run`, и при следующем входе запускается 2.3.0

#### Scenario: Обновление при работающем сервисе
- **WHEN** у пользователя работает сервис, и он сам ставит MSI новой версии с повышением прав
- **THEN** установка завершается с кодом 0 или 3010; при коде 0 в журнале событий есть 1001 с причиной «обновление или удаление программы», и новая версия работает от того же пользователя в том же сеансе

#### Scenario: Обновление другим пользователем
- **WHEN** сервис работает у оператора, а администратор в том же сеансе ставит MSI под своей учётной записью
- **THEN** экземпляр мягко останавливается с 1001 и поднимается при следующем входе оператора; от имени администратора сервис не запускается

#### Scenario: Обновление от SYSTEM
- **WHEN** сервис работает у пользователя, а SCCM ставит MSI новой версии от SYSTEM
- **THEN** установка завершается с кодом 0 или 3010. При коде 0 файлы заменены, при 3010 замена может быть отложена до перезагрузки. Экземпляр без остановки работает на старой версии и отвечает на запросы до выхода пользователя, не подгружая новых файлов. Новая версия запускается при следующем входе, а при 3010 — при первом входе после перезагрузки

#### Scenario: Журнал событий открыт во время обновления
- **WHEN** администратор просматривал события `FilePickerAPI` в Event Viewer (служба журнала событий загрузила файл сообщений), сервис остановлен, и администратор ставит MSI новой версии
- **THEN** установка завершается с кодом 0, служба `EventLog` и зависимые от неё службы работают без перезапуска с прежними PID, а события `FilePickerAPI`, старые и новые, показываются с полным текстом

### Requirement: Удаление MSI
Удаление продукта SHALL убирать файлы сборки и значение `Run`, но MUST оставлять регистрацию источника `FilePickerAPI` и файлы сообщений всех ставившихся версий, чтобы текст прошлых событий читался и после удаления. `.env` администратора и файлы журнала пользователей удаление MUST NOT трогать.

#### Scenario: История событий после удаления
- **WHEN** администратор удалил продукт
- **THEN** при следующем входе сервис не запускается, а прошлые события `FilePickerAPI` в Event Viewer показывают полный текст, без «Не найдено описание»
